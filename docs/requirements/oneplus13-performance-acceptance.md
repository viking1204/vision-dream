## 业务目标

在唯一合格的目标硬件上，用可复现、可比较的场景和统计合同验证 Vision Dream 的模型推理性能、输出质量、可靠性与长时热稳定性；并让性能策略成为可维护且执行语义稳定的版本化预设。验收必须严格区分“可安装/可交互”与“在一加 13 达到性能、可靠性、质量和热稳定性门槛”，防止非目标设备结果或单次最佳成绩形成错误结论。

## 用户/角色

- **性能验收执行者**：在指定一加 13 状态下运行 W1–W7、100 次可靠性与热稳定性流程，留存原始指标和判定结果。
- **性能策略维护者**：创建、修改、删除用户预设，选择或绑定后续请求使用的预设，并能看到回退提示。
- **开发与质量人员**：维护可重复 harness 和机器可读场景，定位未达标原因，针对候选优化做真机 A/B 与质量门禁复测。

## 场景链路

1. 维护者维护版本化性能预设；每个已受理或排队 Job 在入队时冻结不可变 snapshot。
2. 执行者选择指定预设，在一加 13 的已记录环境下，按固定输入分别执行 W1–W7 并采集端到端、分段性能、资源和输出质量证据。
3. 每个最终候选按固定超时执行至少 100 次模型推理；任何定义的失败立即记为失败，不以自动重试掩盖。
4. 候选筛选执行 30 分钟热测；最终胜出配置执行 60 分钟热测、跨 3 次冷启动且至少两轮热测。
5. 质量、回归、性能、可靠性与热稳定性同时通过，才可形成一加 13 对应候选的验收结论；否则仅保留逐候选事实，不能宣称“极限优化完成”。
6. Redmi K30 仅验证非推理交互或 harness，其结果不得进入步骤 2–5 的一加 13 结论。

### 质量与性能统计合同

- **样本量与状态**：每个冷态组至少 5 次；热态先预热 5 次，随后至少采集 30 次。必须区分设备重启冷态、进程冷态、OS page-cache 热态和模型 Context 热态，不得混组；禁止通过 root 清 page cache。
- **采集指标**：报告 p50、p95、MAD 与置信区间（CI）；按场景采集冷启动至 `/health`、Context 加载、CLIP、单步/完整 UNet、VAE decode、首次/第二次生成、峰值 PSS/RSS、HTP spill-fill，以及连续运行温度、降频、吞吐和总耗时。
- **兼容回归门槛**：QAIRT 2.48 使用旧 Context 时，热生成 p50 回归不得超过 2%，p95 回归不得超过 3%；尺寸、seed 行为、资产记录和 API 协议无回归。
- **极限 profile 目标**：同画质下，W1/W2 热生成 p50 与持续吞吐各至少改善 15%；25% 为 stretch goal。未达到目标必须如实保留候选事实，不得声称“极限优化完成”。
- **默认候选准入**：p50 改善至少 3%、p95 至少 5%、持续吞吐至少 5%；或延迟退化不超过 1% 且峰值内存改善至少 10%；两种路径均须 CI 排除噪声。
- **质量门禁**：不改变模型数学语义的优化须在同一 runtime 下保持输出 hash；runtime 或 V79 重编译候选先冻结同 runtime 噪声，再用至少 30 prompt × 4 seed 的 golden set，初始门槛为 SSIM ≥ 0.98、LPIPS ≤ 0.05、CLIP score 相对下降 ≤ 1% 并盲测。所有 tensor 与最终图像均不得出现 NaN/Inf、破图、全黑、色序或 layout 错误。

### 100 次可靠性合同

- **统计对象**：每个最终候选至少 100 次模型推理；预热不计入 100 次。
- **失败定义**：卡死、崩溃、永久 loading、第二次请求失效、协议/资产/seed/尺寸错误，或在冻结后的场景绝对超时内未完成，均计为失败。
- **重试与阈值**：不自动重试，允许失败数为 0；故障后的重试只允许作为独立诊断新 run，不得修改原统计。绝对超时须在 B0 后按场景冻结，候选之间不得变化。

### 热稳定性实验合同

- **时长与轮次**：候选筛选 30 分钟；最终胜出配置 60 分钟，跨 3 次冷启动并至少两轮热测。
- **环境控制**：Wi-Fi ADB、拔除 USB、固定屏幕状态/网络/电量范围，记录环境温度和采样配置。
- **通过条件**：最后四分位吞吐相对最初稳定区间下降不超过 10%；无 severe thermal、崩溃、LMKD、持续 swap 或资源泄漏；卸载/释放后资源回到稳态范围。

### 性能预设 CRUD 合同

- **持久规则**：`name`、`selector`、`configJson`、`revision`、`isFallback` 是本轮需核实并保持的持久规则；性能字段在带版本的 `configJson` schema 表达。
- **可操作对象**：唯一内部 `compatibility` fallback 不可修改、不可删除；其余用户预设可新增、修改、删除。
- **命名与导入**：同名创建/修改拒绝；导入冲突自动编号，不静默覆盖。
- **执行一致性**：已受理或排队 Job 使用不可变 preset snapshot；删除预设不得改变其执行语义。
- **引用删除**：未来默认或模型绑定引用被删除预设时，必须原子回退到 `compatibility` fallback，并提供可见提示。
