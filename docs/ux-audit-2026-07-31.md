# Vision Dream UI/UX 走查报告

- 日期：2026-07-31
- 范围：最新 Debug APK；Redmi K30 首次使用、工作台、创作、模型选择、提示词、资产、性能预设、HTTP/MCP 服务页。
- 边界：未启动模型或服务，未生成、删除或恢复用户资产；模型大列表的密度问题以此前 77 模型设备的界面证据补充，不作为 K30 性能结论。
- 结论：[实锤] 现阶段的问题不止视觉细节，而是创作链路断裂、信息架构混乱、状态与操作不够直观。应先重构交互骨架，再统一视觉系统，不应继续在原页面堆卡片和弹窗。

## P0：创作链路断裂

### 1. 主创作入口没有图生图和局部重绘

工作台“开始创作”进入 `ChatGenerationScreen`，只有文生图；图生图、局部重绘实际位于从模型卡进入的 `ModelRunScreen`。用户按主路径无法发现这些能力，因而会认为功能不存在。

**影响**：核心能力入口与用户心智不一致。

**改造方向**：统一为一个创作工作区，首层显式提供“文生图 / 图生图 / 局部重绘 / 放大”模式。

### 2. 首次使用状态自相矛盾

K30 首页同时显示“已安装 1 个模型”和“尚未加载模型”，却没有明确的“选择并加载模型”主操作。

**影响**：首次使用者无法判断模型是否可用，以及下一步要做什么。

## P1：高频交互问题

### 3. 创作页层级失衡

页面上半部分的模型引导卡过大且重复展示模型信息，提示词输入区被挤到下方；模型、提示词、高级设置、发送之间的主次关系不清。

### 4. 模型选择器无法支撑大量模型

当前仅是单选列表；模型较多时缺少搜索、风格/能力筛选、已加载标记、收藏、最近使用和排序。

### 5. 提示词选择器为空时是死路

空状态只有“取消”，没有“新建提示词”或前往提示词管理器的操作。

### 6. 图标按钮过多且缺少显式含义

提示词、设置、资产布局切换等操作依赖图标辨认；关键动作不应要求用户猜测。

### 7. 模型库混合两类任务

本地模型管理与仓库搜索/下载混在同一页；77 个模型时，大卡片、长描述、巨型模型 ID 区块导致扫描效率低。

### 8. 模型运行状态不够醒目

已加载、排队中、支持图生图/Inpaint、适用后端等应该是模型列表首层信息，而不是进入详情后才判断。

### 9. 资产空状态没有行动出口

空状态只有说明，没有“去创作”入口；“显示全部图片”和布局切换在 0 资产时仍占据首层，语义不成立。

### 10. 图片显示开关语义不清

“显示全部图片”容易被理解为筛选、隐私遮罩或批量选择，当前表达没有明确解释其作用范围。

## P1：服务与性能配置问题

### 11. HTTP 与 MCP 虽实现分离，页面却混成超长表单

主开关、监听地址、端口、复制配置、队列、授权和主机模式没有按用户任务分组。

### 12. 服务运行态不具备可操作性

服务页首屏应展示监听地址、复制按钮、运行时长、当前模型、队列与最近错误；当前说明性文字比连接服务的关键操作更突出。

### 13. MCP 局域网访问的开关样式不清晰

“局域网访问：已关闭（仅本机环回）”呈现为长按钮/状态文本，不像明确的开关，也没有清晰说明开启后的影响。

### 14. 性能控制台状态表达矛盾

“当前生效：持续性能”旁的开关视觉上像关闭；“新建预设”与单张极速卡混排，归属不清。

### 15. 性能参数未按设备与模型能力收敛

K30 的 CPU 模型路径仍突出 HTP 参数。不可用项应隐藏或明确禁用原因，避免把硬件术语暴露给不需要它的用户。

## P2：布局与视觉系统问题

### 16. 首页更像宣传页而不是工作台

英雄区、大卡片和留白消耗过多首屏空间，真正的模型、创作、服务状态被压低。

### 17. 快捷功能卡在窄屏下易折行

四宫格文字易出现不自然换行；控件尺寸、字体大小和留白比例不统一。

### 18. 术语和状态视觉不统一

中英文混用（例如 `CPU Models` / `NPU Models`）；内置预设“只读”也容易被理解为异常或禁用。

### 19. 关键交互缺乏可发现性

模型卡点击、长按等操作没有明确操作提示；用户难以发现选择、管理和运行入口。

### 20. 空状态普遍缺少下一步 CTA

提示词管理器仅有右下角无文字的 `+`；资产、模型和提示词空状态都未把用户引导到下一步任务。

## 业务视角

[业务解读] 应用面向的连续任务是“选模型 → 创作/编辑 → 管理资产 → 对外提供本地能力”。目前页面按技术模块拆分，用户在每个节点都要重新理解入口、状态和术语；这正是“功能找不到、配置看不懂、布局很蠢”的共同根因。

## 后续改造原则

1. 先统一创作工作区和模式切换，消除两套功能不对等的创作入口。
2. 按用户任务重组一级导航：工作台、创作、资产、模型库、服务与自动化。
3. 建立统一的状态、卡片、空状态、主次按钮和图标使用规范。
4. 性能与服务配置采用“推荐预设 + 高级展开”，按设备能力动态收敛参数。
